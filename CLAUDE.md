# CLAUDE.md

Источник правды по устройству Auto HDR: структура, решения и их причины, подводные камни.
Краткая версия для агентов — [AGENTS.md](AGENTS.md), описание для пользователя — [README.md](README.md),
исходный план и список доработок — [PLAN.md](PLAN.md).

## Зачем это

Пользователь забывает переключать HDR вручную, а SDR-картинка в режиме HDR в Windows выглядит
«молочной». Поэтому HDR должен быть включён только во время игры, а всё остальное время — выключен.

## Состояние

- Версия 1.0.6. Компилируется, собирается в `dist\AutoHdr.exe`.
- Проверено на реальной игре: Onimusha: Way of the Sword (Steam, версия 1.0.4 с событиями WMI) — HDR включился при запуске
  и выключился через 10 с после выхода. Что ещё проверено, а что нет — в PLAN.md, раздел «Ход проверки».

## Структура

```
AutoHdr/
  Program.cs            точка входа: разбор --data и режимов без окна, иначе запуск WPF
  App.xaml.cs           жизненный цикл: одна копия, сигналы show/exit, связка движка, трея и окна
  Cli.cs                --launch (обёртка для параметров запуска) и --hdr status|on|off|toggle
  TaskInstaller.cs      автозапуск через планировщик заданий (XML-задача, schtasks /XML)
  Core/
    HdrControl.cs       чтение и переключение HDR через DisplayConfig API
    ProcessWatcher.cs   запуск и завершение процессов: опрос списка раз в 0,25 с
    AutoHdrEngine.cs    игра запущена → включить HDR; все игры закрыты → вернуть SDR
    MonitorRegistry.cs  известные мониторы и флаг «Авто-HDR» для каждого
    AppSettings.cs      настройки, включая PendingRevert
    Infrastructure.cs   AppPaths, InstanceSignals, Log, JsonStore, StartupTrace, Elevation, PathUtil
    Native.cs           P/Invoke
  Library/
    GameRecord.cs       игра, её флаги и данные о поддержке HDR
    GameStore.cs        список игр, поиск игры по пути exe
    Scanners.cs         поиск игр: Steam, GOG, Epic, EA, Ubisoft, Xbox, Rockstar, свои папки
  HdrInfo/
    HdrInfoService.cs   поддержка HDR: Steam Store, PCGamingWiki, сигнатуры в exe; правила статуса
  UI/                   MainWindow (вкладки: игры, мониторы, настройки, журнал), TrayIcon, ViewModels, Snapshot
tools/make-icon.ps1     генерирует AutoHdr/Assets/app.ico (запускать в Windows PowerShell 5.1)
build.ps1               dotnet publish в один файл dist\AutoHdr.exe (framework-dependent, win-x64)
```

## Как это работает

1. `ProcessWatcher` раз в 0,25 с сравнивает список процессов с прошлым и сообщает о новых
   и завершённых. Процессы, запущенные до старта приложения, тоже обрабатываются.
2. `GameStore.Match` ищет игру по пути exe: точное совпадение или самая глубокая папка установки.
3. Если у игры включён авто-HDR, `AutoHdrEngine` включает HDR на мониторах из `MonitorRegistry.Targets`,
   где он ещё выключен, и запоминает их ключи в `AppSettings.PendingRevert`.
4. Когда закрываются все процессы игр, HDR сразу выключается только на мониторах из `PendingRevert`.
   Если включена задержка (`ExitDelay`), сначала проходит `ExitDelaySec` секунд (по умолчанию 5).
   Из `PendingRevert` убираются только мониторы, которые Windows вернула в списке: выключенный
   монитор на DisplayPort пропадает из списка и остаётся в `PendingRevert` до следующего подключения.
   Если монитор вернулся под другим путём устройства, `MonitorRegistry.KeyChanged` переносит ключ.
5. `PendingRevert` сохраняется на диск. Приложение опрашивает мониторы раз в 3 с и при старте
   (`App.RefreshHdrState`) и передаёт список в `AutoHdrEngine.OnDisplaysChanged`. Если игр нет,
   возврат не запланирован, а монитор из `PendingRevert` подключён, режим возвращается. Так HDR выключается
   после сбоя приложения, после игры, которая закрылась, пока HDR ещё включался, и на мониторе,
   которого не было при выходе из игры.

## Решения и причины

Решения ниже принял пользователь. Не меняй их без его согласия.

- **Ручной HDR не трогаем.** Если HDR уже был включён до игры, монитор не попадает в `PendingRevert`
  и после игры остаётся в HDR. Если пользователь сам выключил HDR, `ForgetPending` очищает список.
- **Игры: авто-HDR выключен по умолчанию.** Включается сам, только если HDR подтверждает Steam
  (категория 61 «HDR available») или PCGamingWiki (`hdr` = `true`, `limited` или `always on`). См. `HdrRules`.
  - `hackable` в PCGamingWiki или только упоминания HDR в exe дают статус «Возможно» и флажок не включают.
  - Как только пользователь сам переключил флажок, ставится `UserOverride`, и автоматика флажок больше не меняет.
    Сбросить можно через контекстное меню игры.
- **Мониторы: по явному согласию.** Авто-HDR сам включается только у первого найденного физического
  HDR-монитора, который не похож на телевизор (`MonitorRegistry.LooksLikeTv`). Телевизоры, виртуальные
  дисплеи (Parsec, SudoMaker и т. п.) и все мониторы, подключённые позже, добавляются выключенными.
  Причина: у пользователя бывает подключён только телевизор, и на нём HDR не нужен никогда.
- **Права администратора — только через планировщик.** Манифест `asInvoker`, чтобы обёртка `--launch`
  в параметрах запуска Steam не вызывала UAC. Задача «AutoHDR Enabler» запускает `--tray` при входе
  в Windows с `HighestAvailable` и задержкой 5 с. Права нужны «Ждать HDR»: без них нельзя приостановить
  игру, запущенную с правами администратора.
- **Опрос вместо событий WMI** (с версии 1.0.5). `Win32_ProcessStartTrace` приходил через 0,2–0,5 с
  и стоил около 1,5 мс процессорного времени на каждый запуск любого процесса в системе (git, conhost
  и т. п.). Опрос раз в 0,25 с замечает игру быстрее: около 0,13 мс за проход и 0,03 мс на запуск процесса.
  Опрос идёт в своём потоке, а не в `System.Threading.Timer`: таймер на каждом тике будит ещё поток
  таймера и пул, это вдвое дороже. Прямое чтение ETW отклонено: много кода ради выигрыша в доли миллисекунды.
- **Без внедрения в игры.** Вариант с хуком DXGI внутри процесса игры пользователь отклонил:
  не предлагай его без явной просьбы.
- **«Ждать HDR»** (`GameRecord.HoldUntilHdr`). Процесс игры приостанавливается (`NtSuspendProcess`),
  пока HDR не включится, затем продолжает работу. Нужно играм, которые проверяют HDR в первые секунды
  (например, Cyberpunk 2077). Для онлайн-игр с античитом это рискованно, по умолчанию выключено.
- **Задержка после выхода выключена по умолчанию.** Нужна только играм, у которых лаунчер передаёт
  управление другому exe или которые перезапускаются: без неё HDR мигает. Старое поле `GracePeriodSec`
  (10 с) переименовано в `ExitDelaySec`, чтобы сохранённые 10 с не заменили новые 5 с по умолчанию.
- **`--launch %command%`** — запасной путь для Steam: HDR включается до старта игры. Обёртка ждёт, пока
  закроются все процессы из папки игры (для Steam — `steamapps\common\<игра>`), потому что лаунчер
  часто передаёт управление другому exe. Минимальная задержка здесь — 3 с. Процессы отслеживает тот же
  `ProcessWatcher`: прежний обход путей всех процессов раз в секунду стоил около 3 мс на проход.
  Пауза автопереключения действует и на обёртку: игра запускается без HDR.

## Подводные камни

- **Виртуализация AppData в Claude Desktop.** Claude Desktop — MSIX-пакет. Процессы, запущенные из его
  оболочки (даже с повышением прав), пишут `%LOCALAPPDATA%` в приватную копию внутри
  `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Local\`. Настоящий экземпляр приложения этих файлов
  не видит, и наоборот. Поэтому при тестах из агента передавай `--data <папка>` вне AppData
  (например, во временной папке сессии). Настоящие данные читай через разовую задачу планировщика.
- **schtasks /TR и пробелы.** Путь проекта содержит пробелы (`C:\ai projects\...`). В Windows PowerShell 5.1
  кавычки в `schtasks /TR` ломаются. Приложение поэтому создаёт задачу через `/XML`, а в скриптах удобнее
  `Register-ScheduledTask`.
- **Работающая копия держит exe.** Перед пересборкой её нужно закрыть: `AutoHdr.exe --exit`
  (`build.ps1` делает это сам).
- **Одна копия на сессию.** Мьютекс и события `Local\AutoHdrEnabler.*` создаются с явными правами доступа,
  иначе копия без прав администратора не откроет объекты копии с правами. `--wait` — внутренний флаг
  перезапуска с повышением: новая копия ждёт до 10 с, пока старая закроется.
- **Чтение HDR.** `HdrControl.ReadHdr` сначала пробует `DISPLAYCONFIG_GET_ADVANCED_COLOR_INFO_2`
  (Windows 11 24H2+), затем старый запрос. Включение — `SET_HDR_STATE`, при ошибке — `SET_ADVANCED_COLOR_STATE`.
  После переключения состояние подтверждается опросом до 6 с.
- **Мониторы узнаются по пути устройства**, а при смене разъёма или драйвера — по паре EDID + имя,
  если такая пара одна. У виртуального дисплея SudoVDA путь меняется при каждом подключении (UID257 → UID258).
  `PendingRevert` хранит пути устройств, поэтому при смене пути ключ переносится через `KeyChanged`.
- **WPF + WinForms.** Глобальные `using` для `System.Windows.Forms` и `System.Drawing` убраны в csproj,
  `System.IO` добавлен в `GlobalUsings.cs`: иначе типы конфликтуют.
- **Потоки.** `GameStore.Games` меняется только в потоке интерфейса. `Match` работает по неизменяемому
  снимку и безопасен из любого потока. `HdrInfoService` возвращает изменения через переданный `ui`-делегат.
- **Лимиты запросов.** Steam Store — не чаще раза в 1,5 с, PCGamingWiki — раза в 1,1 с (их лимит 60 в минуту).
- **Скрипты PowerShell.** Файлы `.ps1` с кириллицей держи в UTF-8 с BOM, иначе Windows PowerShell 5.1
  исказит строки.

## Данные и диагностика

- `%LOCALAPPDATA%\AutoHdr`: `settings.json`, `monitors.json`, `games.json`, `log.txt` (ротация в `.old` после 1 МБ).
- Другая папка данных: `--data <папка>` первым аргументом или переменная `AUTOHDR_DATA_DIR`.
- Повреждённый JSON сохраняется как `.bad`, и приложение стартует с пустыми данными этого файла.
- Трассировка запуска: файл `trace.on` рядом с exe или `AUTOHDR_TRACE=1`. Этапы старта пишутся
  в `trace-<pid>.txt` рядом с exe.
- `--snapshot <папка>` рисует вкладки окна в PNG без показа на экране. Так можно проверить вёрстку без пользователя.
