# Auto HDR Enabler — план (ревизия 3: трек B с GUI, мониторами и авто-определением HDR)

> Исходный план, по которому строилась версия 1.0. С тех пор часть решений поменялась: .NET 10 вместо .NET 8, манифест `asInvoker` вместо `requireAdministrator`, другая структура файлов. Актуальное устройство приложения описано в [CLAUDE.md](CLAUDE.md), список доработок — в конце этого файла

## Контекст

**Проблема.** HDR в Windows приходится включать вручную перед игрой, а держать включённым нельзя: SDR-контент в HDR-режиме выглядит мутно. Нужна утилита, которая включает HDR сама, когда запущена игра с HDR, и возвращает SDR после

**Решение по итогам исследования:** своя утилита (трек B). Готовые (Smart HDR Manager, AutoActions) не дают нужной комбинации: выбор мониторов + список игр с ручным включением + авто-определение поддержки HDR

**Окружение (проверено):**
- Windows 11 Pro 26H2 (26300.9711), RTX 5060 Ti, монитор Titan Army P275MS+ (HDR сейчас включён). Иногда подключается телевизор с плохим HDR — для него HDR включать не надо. Два виртуальных адаптера (Parsec, SudoMaker), сейчас неактивны
- API переключения HDR 24H2+ (`SET_HDR_STATE` = 16 / `GET_ADVANCED_COLOR_INFO_2` = 15) на этой сборке работает, проверено
- Библиотеки: Steam (`C:\Program Files (x86)\Steam`, `D:\SteamLibrary`, 21 игра), GOG (Dead Cells, через реестр), EA app без игр, Rockstar Launcher (GTA IV через Steam). Epic/Ubisoft/Xbox не стоят, но сканеры для них сделаем, они дешёвые
- Сборка: есть VS 2026 Build Tools (MSVC, Windows 11 SDK), но **.NET SDK нет**; winget есть (.NET SDK 8.0.426 доступен). Runtime .NET 8 Desktop уже стоит
- Админ-права доступны

## Можно ли заранее узнать, поддерживает ли игра HDR — результат проверки

Прогнал 21 установленную Steam-игру по трём источникам:

| Источник | Как | Качество |
|---|---|---|
| **Steam Store API**, категория 61 «HDR available» (`store.steampowered.com/api/appdetails?appids=ID&filters=categories`) | онлайн, по AppID | Точный, но неполный: флаг есть у Cyberpunk, MK1, Onimusha, EA FC 26, но **нет** у Days Gone и Detroit, хотя у них HDR есть. Разработчики выставляют сами |
| **PCGamingWiki** (`api.php?action=idlookup&field=steamappid|gogid&value=ID` → название страницы → `action=parse&prop=wikitext` → `\|hdr = true/limited/hackable/false/пусто` + `hdr notes`) | онлайн, по Steam AppID или GOG ID; для остальных — по названию через сводную таблицу «List of games that support HDR» (500 строк, одна загрузка, кешируем) | Самый полный: Days Gone = true, Detroit = true, Cyberpunk = limited, Mafia II DE = hackable, GTA IV = false, High On Life = пусто. Лимит 60 запросов/мин, нужен свой User-Agent с контактом. Cargo-запросы закрыты без бот-логина, но они и не нужны |
| **Локальные файлы** (строки `PaperWhite`, `HDR10`, `ST2084`, `scRGB`, `r.HDR.EnableHDROutput` в exe) | офлайн | Только подсказка: у всех UE4-игр и даже у GTA IV есть `HDR10`, у Mafia II — `PaperWhite` без реального HDR. Даёт статус «возможно», не «да» |

**Правило по умолчанию:** Steam-флаг **или** PCGW `true`/`limited` → игра получает статус «HDR есть» и авто-включение **включено** сразу. PCGW `hackable` или только маркеры в файлах → статус «возможно», выключено, пользователь решает. `false`/неизвестно → выключено. Ручной выбор пользователя всегда главнее и не перетирается при повторном сканировании

Запускается с повышением (манифест `requireAdministrator`), автозапуск — задача планировщика с highest privileges, поэтому UAC при входе не появляется

## Поведение

**Мониторы (фича 1).** Вкладка показывает все когда-либо виденные дисплеи по device path + EDID (производитель/код модели), даже отключённые сейчас, с чекбоксом «Включать HDR». При первом запуске включены физические HDR-дисплеи, которые подключены сейчас (P275MS+); имена с Virtual/Parsec/SudoMaker — выключены. **Любой новый монитор, появившийся позже (телевизор), по умолчанию выключен.** Переключение HDR делается только на отмеченных дисплеях. Обновление списка по `WM_DISPLAYCHANGE`

**Игры (фича 2).** Кнопка «Сканировать библиотеки» собирает всё из Steam/GOG/Epic/EA/Ubisoft/Xbox. «Добавить exe» и «Добавить папку» — для своих игр. Сетка: название, источник, бейдж HDR (есть / возможно / нет / неизвестно + заметка PCGW в тултипе), тумблер «Авто-HDR», тумблер «Держать до HDR» (holdUntilHdr). Поиск и фильтры. Повторное сканирование добавляет новые и помечает удалённые, не трогая ручные настройки

**Определение HDR (фича 3).** После сканирования — фоновый опрос источников по правилу выше с прогрессом и кешем. Новые игры со статусом «есть» включаются сразу, остальные выключены

**Наблюдатель.** Событие старта процесса → путь exe → игра по самому длинному совпадению installDir (или точному exe) → если игра включена: включить HDR на отмеченных мониторах (если был выключен — запомнить «включили мы»); при `holdUntilHdr` процесс приостанавливается (`NtSuspendProcess`) до подтверждения HDR и возобновляется. Все процессы игры исчезли → grace period (10 с, настраивается) → вернуть прежнее состояние. Если HDR включил пользователь сам — не выключать. Лаунчеры в папке игры (REDprelauncher) включают HDR ещё до старта самой игры

**Обёртка** `AutoHdr.exe --launch %command%` остаётся для случаев, когда нужен железный порядок без наблюдателя

## Шаги реализации

1. **Инструменты:** `winget install Microsoft.DotNet.SDK.8` (с админ-правами). Проверить `dotnet --list-sdks`
2. **Каркас проекта:** csproj, манифест, трей, пустое окно с вкладками, логгер, settings.json
3. **HdrControl + MonitorRegistry:** перенести проверенный в сессии P/Invoke (структуры `PATH_INFO`, `MODE_INFO` 64 байта, заголовок 20 байт; типы 2/15/16 с fallback 9/10), вкладка «Мониторы», ручная кнопка «Переключить HDR». Проверка на P275MS+
4. **GameStore + сканеры:** Steam и GOG сначала (есть на машине), потом Epic/EA/Ubisoft/Xbox и FolderScan. Вкладка «Игры» с тумблерами и ручным добавлением
5. **HdrInfo:** SteamStoreSource → PcgwSource (idlookup + parse + сводная таблица) → LocalMarkerSource; кеш, троттлинг, правило статусов и дефолтного включения
6. **ProcessWatcher + HdrSession:** WMI-события, сопоставление, grace period, holdUntilHdr, лог
7. **Cli (--launch, --hdr), Install-Task, README.**
8. Прогон проверок ниже, правки

## Проверка

1. Вкладка «Мониторы» показывает P275MS+ с галочкой; ручное переключение работает за 1–2 с. Включить Parsec-дисплей как имитацию телевизора: он появляется **без** галочки, HDR на нём не трогается
2. «Сканировать библиотеки» находит 21 Steam-игру и Dead Cells (GOG). Статусы: Cyberpunk, MK1, Days Gone, Detroit — «есть» и включены; Mafia II DE — «возможно»; GTA IV, CS2 — «нет», выключены; High On Life — «возможно» (маркеры)
3. Запуск Days Gone или Cyberpunk из Steam без правки launch options: HDR включился до появления игры, в настройках игры HDR доступен; выход → через grace period HDR вернулся в прежнее состояние. При заранее включённом HDR ничего не выключается
4. Игра со статусом «нет» (GTA IV) — HDR не трогается
5. Своя игра через «Добавить exe» с holdUntilHdr — стартует уже при активном HDR
6. Выход/вход в систему: задача планировщика запускает трей без UAC, окна не видно
7. Офлайн: сканирование работает, статусы берутся из кеша, без сети показывается «неизвестно» без ошибок

## Нагрузка в простое, 22 октября 2026

Замеры по тактам процессора (`QueryProcessCycleTime`), процессор 3,7 ГГц, в системе около 320 процессов. Claude Desktop запускает git и conhost примерно 27 раз в минуту

| | 1.0.4 | 1.0.5 |
|---|---|---|
| Приложение в простое | 1,4–1,9 мс в секунду | 0,63 мс в секунду |
| Один запуск любого процесса в системе | 1,4 мс (событие WMI) | 0,03 мс |
| Как быстро замечается игра | 0,2–0,5 с | до 0,25 с |

В 1.0.4 больше всего стоили события WMI `Win32_ProcessStartTrace`: каждое обрабатывалось около 1,5 мс в потоке COM. В 1.0.5 их нет, остался только опрос раз в 0,25 с в своём потоке. Опрос через `System.Threading.Timer` с тем же интервалом стоил вдвое больше: 1,22 мс в секунду против 0,60 мс в отдельном замере. Выделения памяти в опросе почти не влияют: 1,13 мс вместо 1,22 мс

Проверено на тестовой копии без прав администратора: копия `ping.exe` в роли игры трижды замечена при запуске и при выходе, каждый раз в пределах 0,25 с. Сама служба WMI тоже тратила время на события, но без прав администратора её не измерить

Не сделано: проверка HDR раз в 3 с стоит около 0,1 мс в секунду. Убрать её можно, только если Windows сообщает о переключении HDR через `WM_DISPLAYCHANGE`. Это не проверено

- Одновременная запись `settings.json` из двух потоков может не сохраниться, но следующее сохранение её повторит

### Проверено 22 октября 2026

Тестовые копии 1.0.5 и 1.0.6 без прав администратора, отдельная папка данных, вместо игры — свой exe, который живёт заданное время

- **Быстрый выход на P275MS+.** Игра живёт от 0,1 до 1,5 с, по два круга. Обе версии каждый раз выключили HDR: на этом мониторе переключение заканчивается раньше, чем процесс успевает закрыться
- **Быстрый выход на медленном мониторе.** Сборки с искусственной задержкой 1,5 с перед переключением, так ведёт себя медленный монитор или телевизор. Игра на 0,3 с: 1.0.5 оставила HDR включённым 3 раза из 3, 1.0.6 — ни разу из 6 запусков по 0,3 и 0,8 с
- **Задержка 5 с.** HDR держится всю задержку, опрос мониторов её не обходит. Повторный запуск во время задержки отменяет её
- **Сбой приложения.** Трей убит, пока HDR включён для игры, игра закрыта. После запуска трея HDR выключился за 4 с
- **Монитор пропал во время задержки.** Виртуальный дисплей SudoVDA убирали во время задержки 8 с и возвращали через 10 с, Windows возвращала ему HDR. 1.0.5 забыла монитор, и HDR остался включённым. 1.0.6 оставила его в `PendingRevert`, перенесла ключ на новый путь устройства (UID257 → UID258) и выключила HDR
- **`--launch`.** На паузе 1.0.5 включила HDR, 1.0.6 — нет. Лаунчер запускает игру на 6 с и закрывается: обе версии держат HDR до конца игры и ещё 3 с. Процессорное время обёртки за 30-секундную игру за лаунчером: 234 мс в 1.0.5 и 94–156 мс в 1.0.6 в двух прогонах. Большую часть этого времени занимает запуск .NET

Не проверено: выключение настоящего монитора на DisplayPort во время задержки и игры с «Ждать HDR» на 1.0.6
